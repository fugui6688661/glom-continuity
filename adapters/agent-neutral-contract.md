# 跨 Agent 接入合同

2026-09-12，用户要求：**要跨所有 Agent。**这是产品覆盖目标，不是全兼容验收结论。Codex、Claude Code、Harness、WorkBuddy、Hermes及其他产品都按可用接口接入；不把品牌、模型或本工具的出生项目当作边界。

## 同一个项目，换谁都能接着做

项目状态保留：项目标识、修订、目标、限制、决定、未决项、下一动作、文件引用与检查结果。接入方必须保留这些含义，不能为了适配聊天窗口而丢掉限制、来源变化或失败信息。

共享的是用户明确选定的项目，不是不同 Agent 的私人聊天、系统提示、账号、密钥或内部记忆库。接收任务不等于获得执行权限，任何接入方式都不能自行宣布任务已经完成。

现有CLI不按品牌限制接收标签。标签只是协作标记，不验证模型身份；增加一个品牌名称不等于新增了一条已验证的集成。

## 按接口接入，不按品牌重写一套系统

| Agent具备什么 | 接法 | 当前真实状态 |
|---|---|---|
| 可运行本地命令，获准访问项目 | 调用同一个CLI，解析完整结果与错误 | CLI本机协议已测；各Agent实际调用仍须逐个验收 |
| 可加载Skill或读取操作说明，并有命令执行工具 | 加载通用`project-continuity` Skill，再调用CLI | 已有通用Skill；每款客户端的发现目录、加载与执行须核查 |
| 只能读上传文件或粘贴文字 | 人工提供审阅后的导出包；提出下一步或修改建议 | 已有review导出；接收方不能据此校验实时文件、领取数据库交接或自动回写 |
| 可连接本地MCP工具 | 官方SDK stdio适配复用同一核心合同 | 已实现；公开协议测试和一个真实Codex恢复任务通过，其他MCP宿主待验；本地命令跨厂商接力见实测记录，不混为MCP通过 |
| 可调用HTTP工具/API，或在其他设备/云端运行 | 经认证的桥接服务访问明确授权的项目 | 待实现；当前没有远端服务、跨设备实时同步或远程写权限 |
| 没有文件、工具、扩展或API入口 | 若可聊天则人工说明；否则暂不能接入 | 不绕过平台限制，不承诺自动打通 |

通用Skill在 `skills/project-continuity/SKILL.md`。只会加载Skill但不能调用工具的Agent，仍属于只读/人工交接，不是完整执行接入。API可调用一个模型，也不等于可以访问某个Agent产品的历史任务或工作环境。

## 所有适配器必须遵守

1. 明确项目与访问范围。当前本机CLI是同一系统用户信任边界；远端接入必须另有认证与项目授权，不能把recipient标签当账号。
2. 恢复时核对项目、修订、检查点和check结果。缺证、来源变化、预算不足都如实保留；不能只取一段正文并标成成功。
3. 保存只走受控接口和当前修订；冲突先重新读取并协调，不盲目重试或直接写SQLite。项目状态的并发保护不等于业务源码具备编辑锁。
4. 领取仅是项目内的一次交接。历史回执不证明外部任务已执行，也不能避免邮件、付款或部署被另一个Agent重复执行。
5. 文件导出是可审阅快照，不是数据库导入或授权令牌。文件型助手的建议由获准的本地接入方复核，再按当前修订保存；未落库必须标明未同步。
6. 不同步正在写入的SQLite文件来假装跨设备协同；后续桥接必须验证授权撤销、重放、并发和断线恢复。当前不宣称这些已通过。

## 稳定的兼容性验收顺序

### context 提示合同（dev1 引入，Alpha.6 包含）

检查点的 `next_action` 是上一次保存者的文字，不是当前用户新授权的指令。`context` 不修改这段文字，正文将它标为 `Recorded next step (not revalidated)`；同时提供 `instruction_authority: none`。

- 引用变化或不可读：`next_action_status: requires_reference_review`，正文先列出 `Reference check: needs_review`、需要复核的提醒和引用问题，再呈现保存的目标与下一步。
- 引用当前一致，或没有引用：`next_action_status: recorded_unverified`。这不证明下一步仍然适用；无引用仍只可按原合同恢复明确缺证的规划。
- `check` 的结构/含义、原检查点及摘要不变；正文和结构化部分取同一次引用检查。MCP 使用同一实现，不另设判断。预算不足仍整条报错，不截去提醒、约束或未知项。

这只是使已观测的文件状态和文字性质更明确，**不是自动判断每句话过期、语义验收或权限执行器**。接手者须结合当前任务和具体交接回执，更新不再合适的下一步。

## 既定兼容性验收路线

在现有实施表B1内推进，不另起主线：

1. 固定本合同和通用Skill；Codex/Harness保留为样例，不绑定产品总目标。
2. 先实现本地MCP适配，让具备该入口的客户端复用同一套项目状态与错误语义；不引入第二套状态库。
3. 按接口类型选代表客户端，记录准确版本，跑保存→更换助手→恢复→实际继续一步→新节点保存；加入来源改变、陈旧修订、重复领取、只读接入等反例。
4. 核查其他客户端并逐个登记；有接口不等于模型遵守操作说明。只能人工交接的明确标为人工。
5. 再实现带认证、项目隔离与撤销的远端桥接，单独验收多设备。不能直接把本机CLI或SQLite公开到网络。

每条兼容记录须有：客户端与版本、入口类型、只读/读写范围、说明加载证据、实际命令或工具调用、接力结果、失败行为、日期。状态分为“未核查、入口已核、协议测试通过、真实Agent接力通过”；不把“格式支持”填成“实接通过”。

## 规范依据与发行边界

- [Agent Skills规范](https://agentskills.io/specification)：用于可移植说明格式；客户端加载与脚本执行仍依赖宿主能力。
- [MCP传输规范（2025-11-25）](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)：MCP使用JSON-RPC并有明确的stdio/Streamable HTTP约定，不能用普通JSON命令输出冒充。HTTP实现须核验Origin、认证及绑定范围等安全要求。

这些是接口设计依据，实现证据另见[实测记录](../docs/verification.md)和[MCP指南](mcp.md)。本地MCP已实现，默认只读；没有远端服务或全局自动安装。9月14日维护者记录了一轮本地命令跨厂商接力，不扩展为全宿主兼容。已有历史ZIP保持不变，新实现与文档须在新发行包中单独标明，不能把旧包说成已含这些更新。
